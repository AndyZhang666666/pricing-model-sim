## 值得看的设计

- 先固定新增用户分母，再追踪解锁、订阅和退出。
- 切换后的人不能在原人群里反复产生收入。
- 扫描只改变一个字段，其余输入保持不变。

## 建议体验路径

1. 选择留存预设，或输入自己的留存与付费假设。
2. 比较三种机制，展开逐月人群、渠道收入和折现回本。
3. 一次扫描一个假设，导出模型版本、输入与结果。

**运行方式：** 条件收入模型，无需 Key。价格变化不会自动改变转化或留存；输入未被真实业务校准，不输出真实最优价。

## 一条完整体验

1. 选择三条合成预设，或拖动 / 输入 D1、D7、D30、D90、D180 留存。零值不被丢弃；锚点保持不增，数字输入支持确认与取消。
2. 调整价格、转化、试用、抽成、获客成本、折现与切换摩擦，比较 12 个月的渠道收入。
3. 展开混合机制逐月状态，核对解锁池、转订阅、切换流失和订阅计费人群。
4. 一次扫描一个字段，其余保持当前输入；查看模型条件下的排序变化，不把涨价的机械收益当作真实价格弹性。
5. 导出假设、模型版本、结果、逐月轨迹和局限。草稿仅存当前浏览器，刷新后重新计算；禁用或损坏存储有恢复路径。

保留原有四工作区、三个预设与四个合成案例。无需登录或 API Key，不上传输入。

## 先统一分母，再比较机制

所有机制的基础序列为“每名最初新增用户在第 k 个月贡献的渠道收入”：

```text
渠道收入 = 计费数量 × 价格 × (1 − 平台抽成)
累计贡献 = 各月收入之和
12 月 LTV = 各月收入按月折现后之和
回本月份 = 累计折现渠道收入首次覆盖 CAC 的月份
```

未付费用户计零。图中用于比较回本的曲线也采用累计折现贡献，与回本月份同口径。CAC=0 时显示不适用，不伪造回本月；零 LTV 不显示成缺失；并列不强行选唯一赢家。

这些是收入指标，不是完整利润，未扣履约、研发、退款等成本。月度存量与日历总收入另列，不拿活跃存量分母与每名新增用户的 CAC 混比。

## 本轮修正：用户离开后，不能又从原池反复出现

模型版本 **conserved-cohort-v2-2026-10-25**：

- 解锁池使用“初始可付费人群中尚未分流的条件份额”。不再把全体新增用户份额误作付费池内比例，造成同一批人重复分流。
- 在月末切换，下月开始订阅计费，不在同月叠加两次全额收费。
- 次数与计费月数直接累计，不从收入除以价格反推，因此价格为零或抽成 100% 也没有 NaN。
- 扫描覆盖字段做深层合并，不把其他手动输入退回默认值。
- 零留存锚点仍进入曲线；包含零的区间明确采用线性比例插值，不静默滤掉。

一个可手算的回归：初始只有 25% 的人会解锁，全部在第一月完成一次解锁后退出，那么每名新增用户累计解锁应为 **0.25 次**。后续月份不能重新生成解锁池。测试同时核对转订阅与流失的累计份额不超过初始可付费人群。

## 产品判断与能力边界

留存、转化、粘性 α 与切换摩擦都是未校准的输入，不是已观察到的用户事实。价格改变不会自动改变转化或留存。因此曲线斜率、切换点与排序都只是条件计算，不是涨价指令、收益承诺或真实最优定价。

月初在册比例代表整月，会抹去月内流失；第一个月从注册时点的 100% 开始，即使 D1 很低也可能高估首月收入。该近似可能改变排序，未承诺误差上限。真实决策需验证价格接受度、付费动机、留存与成本，再做小范围实验。
