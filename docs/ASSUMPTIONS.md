# 核心假设与参数依据

这个文件列出模型里每一个「不是从真实数据拟合出来、而是人工设定」的参数，标明来源或「经验估计」。做这个项目时如果某个地方拿不准，就写在这里，Andy 会逐条复核。

---

## 1. 订阅人群的粘性修正指数 `alpha = 0.85`

**含义**：订阅者相对大盘的月度生存率修正 `subS_k = S_k ^ alpha`（见 `lib/retention.js` 的 `subscriberSurvival`）。

**取值范围**：`alpha ∈ (0, 1]`
- `alpha = 1`：订阅者和普通用户一样容易流失（最保守）
- `alpha < 1`：`S < 1` 时 `S^alpha > S`，订阅者更粘

**当前值**：0.85

**依据**：经验估计。逻辑是「会为内容产品按月付费的人，本来就是高意愿用户，直接用大盘留存会低估」。但这个 0.85 是拍的——我没有真实的「订阅人群 vs 大盘」的留存对照数据。

**敏感性**（短剧预设）：`alpha = 0.75` 时订阅 LTV = 7.32；默认 0.85 时 = 6.29；1.0 时 = 5.56。即 alpha 每降 0.1，订阅 LTV 涨约 12–16%。这是全项目最敏感的一个参数。

**为什么不用「固定加成」**（如每月留存比大盘高 5pp）：见 `docs/DECISIONS.md` 决策 3。

---

## 2. 混合机制的切换摩擦系数 `switchChurn = 0.3`

**含义**：被推荐订阅的人里，直接流失（而不是转为订阅）的比例。`switchChurn = 0.35` 表示推订阅时 35% 的人直接走掉，65% 变成订阅用户。

**当前值**：0.35

**依据**：经验估计。自愿订阅的人（第一次打开 App 就被问「要不要试用」）和被推的人（已经习惯了按集付费）心理状态不同——后者有路径依赖，转化率应该打折。但具体打几折，没有公开基准。

**敏感性**（短剧预设）：`switchChurn = 0` 时混合机制 LTV = 10.12；默认 0.35 时 = 8.69（比无摩擦低 14%）；升到 0.6 时 = 7.67。

**极端情况验证**：
- `switchChurn = 1` 时所有被推订阅的人都流失，混合机制退化为「纯解锁但丢掉一部分用户」——比纯解锁更差，这解释了为什么混合机制在数学上不必然优于解锁
- `switchChurn = 0` 且「推荐阈值」很小时，混合机制逼近纯订阅

---

## 3. 月度时间网格：用月初值而不是日积分

**假设**：第 k 个月的在册比例用 `S_k = r(30 × (k−1))` 代表整月，第 1 个月 `S_1 = r(0) = 1`。

**依据**：取舍决策（见 `docs/DECISIONS.md` 决策 1）——让手算校验能对上，代价是月内波动被抹平。

**误差**：短剧类曲线 D0→D30 从 100% 降到 9%，月初值近似让第 1 个月高估约 10–15%，但后续月份（基数已小）误差变平；对 12 月 LTV 的总影响 <5%。

**如果要改**：在 `lib/retention.js` 的 `monthlySurvival` 里把 `r((k-1)*30)` 换成月内积分 `∫[30(k-1), 30k] r(t) dt / 30`——但这会让所有手算校验都对不上。

## 4. 三条预设留存曲线的锚点

见 `data/GENERATION.md`，全部是经验估计——在公开行业报告的区间里取的代表点，不是任何产品的真实数据。

摘要：
- 短剧类：D1 45% / D7 20% / D30 9% / D90 3.5% / D180 1.8%
- 工具类：D1 32% / D7 24% / D30 17% / D90 9% / D180 5%
- 社交类：D1 50% / D7 34% / D30 20% / D90 11% / D180 6%

**为什么不引用具体报告**：市面上的留存基准报告给出的是行业分布区间，不是单一数字，而且各家口径不同（有的按「打开」、有的按「有效会话」）。上表的具体数值是在这些区间里取的一个代表点，不引用单一报告，因为那些数字放到这里会被误读为「模拟器验证过的行业标准」。它们不是。

## 5. 默认定价参数

| 参数 | 默认值 | 依据 |
|---|---|---|
| 单集解锁价 | ¥2.5 | 短剧类内容的常见定价在 1–3 元/集，取中位 |
| 包月订阅价 | ¥28 | 视频会员的常见价位（爱优腾月卡 15–30 元），取偏高值以体现「内容更垂直」 |
| 获客成本 CAC | ¥8 | 短剧买量的 CPM 约 20–40 元、CTR 约 3–8%、落地转化 10–20%，折算单用户成本约 5–15 元，取中位 |
| 平台抽成 | 30% | 应用商店（App Store / Google Play）的标准分成 |
| 试用天数 | 3 天 | 短剧类产品的常见试用周期（工具类往往 7–14 天） |

这些是「长得像真实业务」的默认值，不是优化后的最优值。用户可以在界面里随意改。

## 6. 锚点区间内用插值、不用全局拟合

**假设**：D1~D180 之间，`r(d)` 在相邻锚点间做对数线性插值，精确穿过每个锚点；全局幂律 / 指数形式只负责 D180 之后的尾部外推。

**依据**：第一版用单条全局幂律穿 5 个锚点，短剧预设的 D30 实测 9% 被拟合成 5.6%（误差 40%），D30 恰好是决定「订阅 vs 解锁」的核心输入——用户拖到 9%，模型算的却是 5.6%，结论就是错的。曲线必须穿过用户给的点。详见 `docs/DECISIONS.md` 决策 2。

**代价**：曲线不再有全局解析解——但这不影响使用，`curve.r(d)` 仍然是确定性函数。

## 7. 解锁机制的「人均月解锁次数」= 付费者占比 × 付费者月均解锁

**参数**：
- `payerShare = 0.32`（32% 的在册用户会解锁付费内容）
- `unlocksPerPayerMonth = 10`（付费者平均每月解锁 10 集）
- `payerDecay = 0.9`（付费者占比按月衰减 10%，模拟「后期用户越来越不愿付费」）

**依据**：经验估计。32% 这个付费率是短剧类产品的公开常识范围（各家报告给的区间约 20–50%，取中偏低）；10 集 / 月对应「一周看 2–3 集」的中度用户。

**为什么要拆成两项**：如果只用「全员人均解锁次数 = 3.2 次 / 月」（32% × 10），模型算不出「付费者本身的粘性」和「付费意愿随时间衰减」这两个效应——但这两个是解锁机制 LTV 的关键驱动。拆开后可以分别调 `payerShare` 和 `payerDecay`，敏感性分析也更清楚。

---

## 8. 免费集数的「付费窗口期」计算

**假设**：免费 N 集、每月上新 M 集，第 1 个月的「付费窗口期」= `max(0, min(1, 1 - N/M))`。含义是：如果 N ≥ M，用户第 1 个月全在免费区，窗口 = 0；如果 N = 0，窗口 = 1。

**依据**：简化假设。真实情况里「免费 3 集」可能是「前 3 集永久免费」或「每部剧前 3 集免费」，两者的付费窗口不同——但模型不区分这两种，统一按「前 N 集免费」处理。

**敏感性**（短剧预设）：免费集数 0 → 5 → 10，解锁机制 LTV 从 6.80 降到 5.68 再降到 4.56（-33%）；订阅不受影响（订阅用户不看免费集数）。

## 需要 Andy 本人复核的清单

1. `alpha = 0.85`（第 1 条）—— 订阅人群的粘性修正，影响订阅 LTV 约 ±10%
2. `switchChurn = 0.35`（第 2 条）—— 混合机制的切换流失率，影响混合 LTV 约 -14%（相对无摩擦）
3. 三条预设曲线的锚点（第 4 条）—— 是否「长得像」真实业务
4. 默认定价参数（第 5 条）—— CAC ¥8、月费 ¥28、单价 ¥2.5 是否合理
5. 解锁机制的付费率 32% 和月均解锁 10 次（第 7 条）—— 是否在常识范围内

如果你有真实业务数据，所有这些参数都可以在界面里改，不需要改代码。
